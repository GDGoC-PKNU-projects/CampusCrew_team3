# 실패 처리 (FAILURE_HANDLING)

AI 응답은 항상 믿을 수 없다는 전제로 다룬다. 실패 사유를 구현 전에 고정한다. 근거: `doc/ai/AI_SPEC.md` §9, `doc/ai/AI_GUIDE.md` §8 STEP2.

## 실패 판정 표

| 사유 | 판정 조건 | 적용 기능 | 재시도 | 사용자 노출 |
| --- | --- | --- | --- | --- |
| 빈 응답 | 모델 응답이 비었거나 공백뿐 | 전체 | 1회 | "AI 응답을 받지 못했습니다. 다시 시도해주세요." |
| JSON 형식 오류 | 파싱 실패 / 스키마 불일치 | 전체 | 1회 | "AI 응답 형식이 올바르지 않습니다. 다시 시도해주세요." |
| title 누락 | `items[].title`이 빈 항목 존재 | 액션 아이템 | 0회(해당 항목 제거 후 전부 빔이면 실패) | "추출된 할 일이 없습니다." |
| tone 잘못 | `tone`이 허용값 밖 | 톤 변환 | 0회 | 요청 검증 단계에서 400 |
| 출처 없음 | `sources`가 빈 배열 | Q&A(STEP4) | 0회 | "관련 문서를 찾지 못했습니다." |
| 타임아웃 | LLM 응답 지연 | 전체 | 0회 | "AI 응답이 지연됩니다. 잠시 후 다시 시도해주세요." |

## 재시도 기준

- 재시도는 **빈 응답 / JSON 오류**에만 최대 **1회**.
- 의미상 실패(출처 없음, title 없음, tone 위반)는 재시도하지 않고 바로 실패.
- 타임아웃은 재시도하지 않음(중복 호출 비용 방지).

## 응답 형식

- AI 서버는 실패 시 HTTP 422(검증/AI 실패) 또는 400(입력 오류)로 구조화 에러 반환. 500은 예기치 못한 오류에만.
- 에러 바디:
```json
{ "error": { "code": "EMPTY_RESPONSE", "message": "AI 응답을 받지 못했습니다." } }
```
- `code` 값: `EMPTY_RESPONSE`, `INVALID_JSON`, `EMPTY_TITLE`, `INVALID_TONE`, `NO_SOURCES`, `LLM_TIMEOUT`.
- Spring은 이 에러를 받아 공통 `ApiResponse{success:false, message}`로 변환한다.

## 원칙

- 실패를 숨기지 않는다(가짜 성공 응답 금지).
- AI 실패가 일반 CRUD를 막지 않는다(AI_SPEC §4).
- 프론트는 에러 문구를 보여주고 기존 입력값을 유지한다(AI_SPEC §7).
