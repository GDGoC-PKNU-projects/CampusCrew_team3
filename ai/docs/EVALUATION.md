# 평가 기준 (EVALUATION)

기능별 "좋은 응답" 기준을 고정해 구현 후 품질 점검에 쓴다. 근거: `doc/ai/AI_GUIDE.md` §9, §STEP6.

## 1. 액션 아이템 추출

| 항목 | 좋은 응답 기준 |
| --- | --- |
| 실행 가능성 | 각 `title`이 실제 행동 가능한 할 일. 배경/감상 문장 아님. |
| 요약과 분리 | 회의 요약이 아니라 할 일만 추출됨. |
| hint 정확 | 본문에 단서 있을 때만 `assigneeHint`/`dueDateHint` 채움. 없으면 `null`. |
| 환각 없음 | 본문에 없는 담당자/날짜 미생성. |
| 형식 | `title` 항상 존재, `dueDateHint`는 `YYYY-MM-DD` 또는 `null`. |

## 2. 톤 변환

| 항목 | 좋은 응답 기준 |
| --- | --- |
| 의미 보존 | 핵심 사실(시각/장소/대상)이 그대로 유지됨. |
| 톤 일치 | `SHORT`=짧음, `FORMAL`=정중, `PLAIN`=평이. |
| 사실 무추가 | 새 정보 없음. |
| 길이 | 원문 대비 과도하게 길지 않음. |

## 3. 진행 상황 요약 (STEP4)

| 항목 | 좋은 응답 기준 |
| --- | --- |
| 핵심 중심 | 단순 나열 아닌 핵심 변화 정리. |
| 비장황 | 짧은 보고체. |
| 근거 | 실제 팀 데이터 기반. |

## 4. 팀 문서 Q&A (STEP4)

| 항목 | 좋은 응답 기준 |
| --- | --- |
| 출처 정확 | `sources`가 실제 답변 근거와 일치(citation accuracy). |
| 팀 범위 | 같은 팀 문서만 참조. |
| 정직성 | 근거 없으면 "모른다". |
| 형식 | `sources` 최대 3개, `type/id/title` 포함. |

## 점검 순서 (STEP6)

톤 변환 → 액션 아이템 → 요약 → Q&A. 로컬뿐 아니라 배포 환경(e2-standard-2/Docker 네트워크)에서 같은 기준으로 재점검.
