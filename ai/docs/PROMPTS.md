# 프롬프트 초안 (PROMPTS)

기능별 프롬프트를 **역할 / 입력 / 출력 / 금지** 4분할로 고정한다. 기능 설명과 출력 형식 설명을 섞지 않는다. 근거: `doc/ai/AI_GUIDE.md` §8 STEP2~3, `doc/ai/AI_SPEC.md` §5.

> 출력 형식은 Gemini structured output(`response_mime_type=application/json` + `response_schema`)으로 강제하고, 수신 후 Pydantic으로 재검증한다. 프롬프트 본문에 "JSON만 출력" 류 지시도 함께 둔다.
> 코드 동기화 위치: `ai/app/prompts/`.

---

## 1. 액션 아이템 추출 (`prompts/action_items.py`)

**역할**
- 너는 회의록에서 실행 가능한 할 일 후보를 뽑는 추출기다.
- 회의 전체를 요약하지 않는다. 실제로 누군가 행동해야 하는 항목만 뽑는다.

**입력**
- 회의록 본문 1개(`content`).

**출력**
- `items` 배열. 각 항목은 `title`, `assigneeHint`, `dueDateHint`.
- `title`: 할 일 한 줄. 필수.
- `assigneeHint`: 본문에 담당자 단서가 있으면 그 표현, 없으면 `null`.
- `dueDateHint`: 마감일 단서가 있으면 `YYYY-MM-DD`로 정규화, 없으면 `null`.

**금지**
- 본문에 없는 담당자/날짜를 지어내지 않는다.
- 회의 요약, 배경 설명, 감상 문장을 넣지 않는다.
- 상대 표현("다음 주")을 임의 날짜로 못 박지 않는다. 확실히 환산 가능할 때만 날짜화, 아니면 `null`.
- `title`이 없는 항목은 만들지 않는다.

**few-shot (1쌍)**
- 입력: `"로그인 API는 백엔드A가 다음 주 금요일까지 검증하기로 했다. 디자인은 추후 논의."`
- 기대 출력:
```json
{ "items": [ { "title": "로그인 API 검증", "assigneeHint": "백엔드A", "dueDateHint": null } ] }
```
(디자인 항목은 행동 주체·내용이 불명확 → 제외. "다음 주 금요일"은 기준일 없으면 `null`.)

## 2. 톤 변환 (`prompts/tone.py`)

**역할**
- 너는 공지 문서의 톤만 바꾸는 변환기다. 내용(사실)은 그대로 둔다.

**입력**
- 원본 본문(`content`), 목표 톤(`tone`).
- 톤 정의:
  - `SHORT`: 핵심만 짧게, 군더더기 제거.
  - `FORMAL`: 정중한 존댓말 공지체.
  - `PLAIN`: 쉽고 평이한 표현.

**출력**
- 변환된 본문 문자열(`content`) 하나.

**금지**
- 새로운 사실, 날짜, 인원, 장소를 추가하지 않는다.
- 원문에 있는 핵심 정보를 빼지 않는다.
- 원문보다 크게 길어지지 않는다.
- 머리말/꼬리말("아래는 변환된 내용입니다") 추가 금지.

**few-shot (1쌍, FORMAL)**
- 입력: `content="내일 3시 회의함"`, `tone="FORMAL"`
- 기대 출력:
```json
{ "content": "내일 오후 3시에 회의를 진행합니다." }
```
(시각 정보 유지, 표현만 정중체. 새 정보 없음.)

## 3. 진행 상황 요약 / 4. 팀 문서 Q&A

STEP4 범위. 프롬프트는 해당 STEP에서 작성. 원칙은 동일(역할/입력/출력/금지 분리). Q&A는 출처(`sources`) 강제 + 근거 없으면 "모른다".
